# Audit Notes

Repository: `pusparghya-manna/quiz-bot-by-pusparghya`
Commit audited: `c68b0d5` on `main`

## Deployment surfaces

- `frontend/` is the documented production teacher dashboard deployed to Vercel and proxied to Railway.
- `webapp/` is a separate Telegram student mini app with its own Vercel deployment.
- The repository also includes a root `privacy.html`.

## Preliminary evidence

- The teacher frontend already contains a `NotFound` page and SPA rewrites in `frontend/vercel.json`.
- The teacher frontend has multiple pages/components and route-aware behavior; metadata appears to be centralized in `frontend/index.html` rather than clearly configured per page.
- The student webapp has loading skeletons, loading/error state code, mobile CSS breakpoints, and image alt attributes in many components, but at least one decorative image uses an empty alt attribute and needs classification.
- Existing image assets, if any, must be inventoried and checked for dimensions/format/compression.
- No conclusive evidence yet for robots.txt, sitemap.xml, complete favicon set, Open Graph image, cookie banner, analytics, thank-you page, terms page, real contact address, or a sticky mobile CTA.
- The repository must be verified across both deployable frontends before deciding which surface receives each improvement.

## Live-site verification

- Teacher dashboard URL redirects to `/login` and renders the title `Quiz Bot by Pusparghya`, a teacher-dashboard label, sign-in/register tabs, username/password inputs, and a visible `Sign in` CTA.
- The teacher login page visibly uses the favicon/logo asset. The above-the-fold CTA exists, but the homepage does not currently present a marketing-style hero or teacher-focused CTA block.
- Student mini-app URL is publicly reachable only to the extent of its Telegram gate. Outside Telegram it displays `Telegram login required`, instructs users to open the app inside Telegram, and reports that access is blocked without Telegram `initData`. This prevents full browser verification of authenticated student flows.
- The student app is therefore verified from source code for internal loading/error/exam-action behavior, not from an authenticated browser session.

## Verification limitation

A Telegram-authenticated session was not available in the browser. Do not claim that authenticated student UI was visually inspected.
